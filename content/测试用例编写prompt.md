3. ## 个性化拆分偏好（必须严格遵守）

  3.1 用例数量策略
  原则：测试用例数量尽可能多，而不是尽可能少。
  禁止将多个不同场景、不同输入条件、不同状态、不同按钮行为合并为一条用例。
  以下类型允许合并为一条用例：
  单条件查询（同一页面所有单字段查询）
  必填项校验（同一页面全部必填项）
  数据回显（同一页面所有字段回显）
  3.2 状态 / 按钮行为拆分
  若列表中不同状态对应不同按钮可见性或可用性，则每个状态必须独立拆分测试点。例如：
  状态 = 预警中：解除按钮可用、恢复按钮禁用或隐藏  
  状态 = 手动解除：恢复按钮可用、解除按钮禁用或隐藏  
  状态 = 自动解除：两个按钮均禁用或隐藏  
  每个状态 = 一条独立测试用例。
  3.3 字段校验拆分
  每个字段的校验项必须独立形成测试点。例如：
  必填校验  
  长度限制  
  类型校验  
  格式校验  
  唯一性校验  
  文件大小、文件类型、文件名长度  
  字段回显  
  3.4 流程状态拆分
  每个状态流转必须独立拆分，例如：
  待提交 → 已提交  
  待审批 → 审批通过  
  待审批 → 审批驳回  
  待评价 → 评价中  
  评价中 → 已归档  


4. ## 防幻觉协议（ID 锁 / 数量锁 / 一致性锁）

  4.1 全局唯一 ID 锁定
  所有测试点必须分配编号：TC-001、TC-002、TC-003…  
  ID 一经分配不可修改、不可删除、不可跳号  
  后续新增必须从最大 ID 继续编号  
  第二阶段与第三阶段必须完全遵守第一阶段的 ID 顺序
  4.2 数量锁
  第一阶段必须明确输出测试点总数 N  
  第二阶段必须严格产生 N 条测试用例  
  第三阶段脚本中的 EXPECTED_TOTAL 必须等于 N  
  脚本末尾必须进行数量校验
  4.3 脚本内容一致性锁
  Python 脚本中的所有用例内容必须与第二阶段完全一致  
  禁止修改、优化、重写、合并或删减任何内容  
  字段名称、步骤顺序、预期结果必须保持 1:1 对齐


5. ## 三阶段执行流程


★ 第一阶段：测试点大纲 + ID 锁定
输出要求
输出按模块分层的测试点大纲（Markdown 列表）。
每个最小粒度的原子测试点必须分配一个全局唯一 ID，全模块统一编号。
输出测试点列表表格，包含：
ID  
模块  
测试点标题  
重要程度（P0–P3）
阶段结束语（必须严格输出）
【防幻觉校验】已锁定测试点总数：[N]，ID 范围：[TC-001] 至 [TC-0NN]。


★ 第二阶段：测试用例编写（严格按 ID 顺序）
重要程度定义（完整保留）
P0：核心业务闭环（冒烟）  如创建、审批、关闭等关键流程  
P1：基础功能操作  如增删改查、导入、导出  
P2：普通功能与交互，包括但不限于：  排序、分页、下拉框、单选、多选、图表交互、地图缩放、地图拖拽  
P3：字段级校验，包括但不限于：  必填、长度、类型、格式、唯一性、回显
标题规范
P0/P1/P2：标题必须以“功能验证”或“流程验证”结尾  
P3：标题必须以“校验xxx”开头  
步骤与预期规则
每条步骤必须对应一条预期  
数量必须完全一致  
描述应清晰可执行，不允许歧义  
第二阶段结束语
已完成 [N] 条详细用例编写，准备生成脚本。


6. ## 第三阶段：Python 脚本生成规范（最终格式标准）

  6.1 配置区变量（必须包含）
  EXPECTED_TOTAL = N
  OUTPUT_FILE = "test_cases.xlsx"
  DEFAULT_OWNER = "宁瑞瑞"
  DEFAULT_STATUS = "就绪"
  DEFAULT_CASE_TYPE = "功能测试"
  DEFAULT_TEST_TYPE = "手动"
  DEFAULT_STAGE = "功能测试阶段"


6.2 test_cases_data 数据结构（最终唯一标准）
每条用例必须采用如下字典结构，且键名必须一致：
{
  "id": "TC-001",
  "module": "模块名称",
  "priority": "P1",
  "title": "模块-菜单：xxx功能验证",
  "steps": "1. 步骤A\n2. 步骤B\n3. 步骤C",
  "expected": "1. 预期A\n2. 预期B\n3. 预期C"
}
关键要求：
steps 与 expected 必须是多行字符串  
每行必须使用编号（例如“1. xxx”）  
禁止使用 list[str]  
步骤与预期行数必须一致  


6.3 Excel 字段顺序（不可更改）
["模块", "编号", "标题", "状态", "维护人", "用例类型", "重要程度", "测试类型",
 "预估工时", "剩余工时", "关联工作项", "前置条件", "步骤描述", "预期结果",
 "关注人", "备注", "适用阶段", "关联模块"]
固定规则：
“编号”必须为空字符串 ""  
步骤描述与预期结果写入字符串  
必填字段包括：模块、标题、状态、维护人、用例类型、重要程度、测试类型、步骤描述、预期结果、适用阶段
前置条件为非必填字段，是具体情况填写，若有则填写，若无前置条件可以保持为空
必须保持为空的字段包括：编号、预估工时、剩余工时、关联工作项、关注人、备注、关联模块


6.4 控制台输出格式
[1/N] 生成用例: TC-001 - xxx功能验证


6.5 数量校验（必须执行）

    print("校验通过")
